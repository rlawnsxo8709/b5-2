# 병합 정렬 (Merge Sort)

`LOG --sort-by=date|author`와 `ANCESTORS`의 같은 거리 조상 정렬에 쓰인다.
구현은 `mini_git/sorting.py`의 `merge_sort` (`sorted()`, `list.sort()`는 미션에서 금지).

## 1. 아이디어: 나누고, 정렬하고, 합친다

1. **나눈다**: 리스트를 반으로 가른다. 원소가 1개 이하가 될 때까지 반복한다. (1개짜리는 이미 정렬된 상태)
2. **합친다**: 정렬된 두 리스트의 맨 앞 원소끼리 비교해 작은 쪽을 결과에 넣는다. 한쪽이 바닥나면 나머지를 그대로 붙인다.

### 전체 그림 (`[5, 2, 4, 7, 1, 3, 2, 6]`)

```
                 [5, 2, 4, 7, 1, 3, 2, 6]
                /                        \
        [5, 2, 4, 7]                [1, 3, 2, 6]          ← 나누기
         /        \                  /        \
     [5, 2]     [4, 7]           [1, 3]     [2, 6]
      /  \       /  \             /  \       /  \
    [5]  [2]   [4]  [7]         [1]  [3]   [2]  [6]       ← 1개씩 (정렬됨)
      \  /       \  /             \  /       \  /
     [2, 5]     [4, 7]           [1, 3]     [2, 6]        ← 합치기
         \        /                  \        /
        [2, 4, 5, 7]                [1, 2, 3, 6]
                \                        /
                 [1, 2, 2, 3, 4, 5, 6, 7]
```

### 합치기 과정 (`[2, 4, 5, 7]` 과 `[1, 2, 3, 6]`)

```
left  = [2, 4, 5, 7]     right = [1, 2, 3, 6]     merged = []

 2 vs 1  → 1 이 작다           merged = [1]
 2 vs 2  → 같다, left 먼저     merged = [1, 2]       ← 안정성
 4 vs 2  → 2 가 작다           merged = [1, 2, 2]
 4 vs 3  → 3 이 작다           merged = [1, 2, 2, 3]
 4 vs 6  → 4 가 작다           merged = [1, 2, 2, 3, 4]
 5 vs 6  → 5 가 작다           merged = [1, 2, 2, 3, 4, 5]
 7 vs 6  → 6 이 작다           merged = [1, 2, 2, 3, 4, 5, 6]
 right 바닥 → left 의 나머지 [7] 를 붙인다
                               merged = [1, 2, 2, 3, 4, 5, 6, 7]
```

## 2. 코드

```python
def merge_sort(items, key=lambda x: x):
    pairs = [(key(item), item) for item in items]     # 키는 원소마다 한 번만 계산
    return [item for _, item in _sort_pairs(pairs)]

def _sort_pairs(pairs):                               # 나누기
    if len(pairs) <= 1:
        return pairs
    mid = len(pairs) // 2
    return _merge(_sort_pairs(pairs[:mid]), _sort_pairs(pairs[mid:]))

def _merge(left, right):                              # 합치기
    ...
    if right[j][0] < left[i][0]:                      # 오른쪽이 "엄격히" 작을 때만 오른쪽을 취함
        merged.append(right[j]); j += 1
    else:                                             # 같으면 왼쪽을 먼저 → 안정 정렬
        merged.append(left[i]);  i += 1
```

- 입력 리스트는 바꾸지 않고 **새 리스트**를 돌려준다.
- `key` 함수로 정렬 기준을 바꾼다. 비교는 키끼리 `<`만 쓴다.

## 3. 시간복잡도

```
레벨 0:  [ n 개 ]                       합치는 비용 n
레벨 1:  [ n/2 ] [ n/2 ]                합치는 비용 n
레벨 2:  [n/4][n/4][n/4][n/4]           합치는 비용 n
  …                                     …
레벨 log₂n:  [1][1][1] … [1]            (끝)
```

- 나누는 층이 **log n** 개
- 각 층에서 모든 원소를 한 번씩 합치므로 **n**
- 합치면 **O(n log n)**

| | 평균 | 최악 | 추가 메모리 | 안정성 |
|---|---|---|---|---|
| 병합 정렬 | O(n log n) | O(n log n) | O(n) | 안정 |
| 버블 정렬 (참고) | O(n²) | O(n²) | O(1) | 안정 |

커밋이 1만 개면 비교 횟수가 버블 정렬 약 1억 번 대 병합 정렬 약 13만 번 정도로 벌어진다.
최악의 경우에도 O(n log n)이 유지되는 것이 병합 정렬의 장점이다.

## 4. 안정 정렬 (Stable Sort)

**키가 같은 원소들의 원래 순서를 유지하는 정렬.**
합칠 때 값이 같으면 **왼쪽(원래 앞에 있던 쪽)을 먼저** 넣기 때문에 안정적이다.

### 예: 작성자 기준 정렬

```
입력 (생성 순서)               작성자 기준 정렬 결과

 1. Bob                         2. Alice   ┐ Alice끼리는 원래 순서(2 → 4)
 2. Alice                       4. Alice   ┘
 3. Bob                         1. Bob     ┐ Bob끼리도 원래 순서(1 → 3)
 4. Alice                       3. Bob     ┘
```

불안정 정렬이면 `4. Alice`가 `2. Alice`보다 앞에 올 수도 있다.

### 이 프로젝트에서

정렬 키 끝에 생성 순번 `seq`를 붙여서 동률을 확실하게 가른다.

| 명령 | 키 |
|---|---|
| `LOG --sort-by=date` | `(timestamp, seq)` |
| `LOG --sort-by=author` | `(author, seq)` |

같은 초에 만든 커밋이나 같은 작성자의 커밋이 항상 같은 순서로 나온다.

## 5. 왜 병합 정렬을 골랐나

- 평균·최악이 모두 **O(n log n)** 으로 일정하다.
- **안정 정렬**이라 동률 처리가 자연스럽다.
- 미션 목표가 "평균/최악 시간복잡도와 안정성 설명"이다. 분할 정복 구조가 분명해서 설명하기 좋다.
- 단점은 추가 메모리 O(n)이 든다는 것이다. 이 프로젝트 규모에서는 문제되지 않는다.

버블 정렬이 구현은 더 쉽지만 O(n²)이라 커밋이 많아지면 느려진다.
