# 위상 정렬 (Topological Sort)

`LOG` 명령이 "부모 커밋이 항상 자식 커밋보다 먼저 출력"되게 하는 알고리즘이다.
구현은 `mini_git/graph.py`의 `topo_order` (Kahn 알고리즘).

## 1. 위상 정렬이란

**방향이 있고 순환이 없는 그래프(DAG)에서, 모든 화살표가 앞에서 뒤로만 향하도록 노드를 한 줄로 세우는 것.**

화살표 `A → B`는 "A가 B보다 먼저 와야 한다"는 뜻이다.
커밋 그래프에서는 **부모 → 자식** 방향으로 읽는다.

### 일상 예: 옷 입는 순서

```
속옷 ──► 바지 ──► 벨트 ──► 겉옷
          │
          └────► 신발 ◄──── 양말
```

| 순서 | 가능? | 이유 |
|---|---|---|
| 속옷, 바지, 벨트, 양말, 신발, 겉옷 | O | 모든 화살표가 앞→뒤 |
| 양말, 속옷, 바지, 신발, 벨트, 겉옷 | O | 정답은 여러 개일 수 있다 |
| 신발, 양말, … | X | 신발이 바지·양말보다 앞에 올 수 없다 |

### 커밋 그래프에서

```
        ┌── m1 ──┐
  root ─┤        ├── M ── c
        └── f1 ──┘
```

| 순서 | 가능? | 이유 |
|---|---|---|
| root, m1, f1, M, c | O | 부모가 항상 자식보다 앞 |
| root, f1, m1, M, c | O | m1과 f1은 서로 제약이 없다 |
| root, m1, M, f1, c | X | M의 부모 f1이 M보다 뒤 |
| m1, root, … | X | 자식이 부모보다 앞 |

## 2. 왜 DAG에서만 가능한가

순환이 있으면 "A가 B보다 먼저"와 "B가 A보다 먼저"를 동시에 만족할 수 없다.

```
   ┌──────────┐
   ▼          │
   A ───────► B        A → B, B → A : 어느 쪽을 먼저 놓아도 위반
```

그래서 커밋 그래프는 DAG여야 한다. 이 프로젝트에서는 새 커밋이 **이미 존재하는 커밋만** 부모로 삼고 커밋이 불변(`frozen`)이라 순환이 만들어질 수 없다.

## 3. Kahn 알고리즘

핵심 아이디어: **"아직 출력 안 된 부모가 하나도 없는 커밋"은 지금 출력해도 된다.**
하나 출력하면 그 자식들은 기다리는 부모가 하나 줄어든다. 이것을 반복한다.

### 절차

1. 커밋마다 **아직 출력 안 된 부모 수**(`waiting`)를 센다.
2. `waiting == 0`인 커밋(루트)이 꺼낼 수 있는 후보다.
3. 후보 하나를 꺼내 결과에 추가한다.
4. 꺼낸 커밋의 자식들의 `waiting`을 1씩 줄인다. 0이 되면 후보가 된다.
5. 후보가 없어질 때까지 3~4를 반복한다.
6. 결과 개수가 전체보다 적으면 **순환**이 있는 것이다.

### 손으로 따라가기

```
        ┌── m1 ──┐
  root ─┤        ├── M
        └── f1 ──┘
```

`nodes = [root, m1, f1, M]` (생성 순서), 처음 `waiting = [0, 1, 1, 2]`

| 단계 | 꺼냄 | waiting 변화 | 새 후보 | 결과 |
|---|---|---|---|---|
| 시작 | | `[0, 1, 1, 2]` | root | |
| 1 | root | m1→0, f1→0 | m1, f1 | root |
| 2 | m1 | M→1 | (없음) | root, m1 |
| 3 | f1 | M→0 | M | root, m1, f1 |
| 4 | M | | | root, m1, f1, M |

`M`은 부모가 둘이라 **둘 다 나온 뒤에야** 꺼낼 수 있다. 그래서 부모가 항상 자식보다 먼저 온다.

### 순환 검출

```
nodes = [C, A, B]     A의 부모 = B,  B의 부모 = A,  C는 독립
```

C만 꺼낼 수 있고, A와 B는 서로를 기다려서 `waiting`이 0이 되지 못한다.
결과는 `[C]` (1개) ≠ 전체 3개 → `ValueError("cycle detected in commit graph")`.

## 4. 이 프로젝트의 구현

```python
position = {h: i for i, h in enumerate(nodes)}    # 해시 → 인덱스
waiting  = [0] * len(nodes)                       # 아직 출력 안 된 부모 수
children = {h: [] for h in nodes}                 # 부모 → 자식 목록
```

- `parents_of`는 "커밋 → 부모 목록" 함수다. 저장소를 직접 모르게 하려고 인자로 받는다.
- 커밋은 부모만 알기 때문에, 꺼낸 뒤 누구의 `waiting`을 줄일지 알려면 반대 방향 연결 `children`이 필요하다.

### 큐 대신 `lo`와 `ready`를 쓰는 이유

일반 Kahn은 후보를 큐에 담는다. 이 구현은 **꺼낼 수 있는 후보가 여럿이면 `nodes`에서 앞선 것(= 먼저 만든 커밋)을 먼저** 꺼내려고 인덱스 순으로 훑는다.
같은 입력이면 항상 같은 결과가 나온다(결정적).

```
ready: [F  F  T  T  F  T ...]
        ▲
        lo  ← "이 위치 앞에는 꺼낼 수 있는 노드가 없다"
```

- `lo`부터 오른쪽으로 훑어 `ready`가 참인 첫 칸을 꺼낸다.
- 꺼낸 뒤 새로 꺼낼 수 있게 된 자식이 `lo`보다 **앞쪽**이면 `lo`를 그 칸으로 되돌린다.

### 시간복잡도

| 입력 순서 | 복잡도 | 이유 |
|---|---|---|
| 생성 순서 (부모가 항상 앞) | **O(V + E)** | 자식은 항상 부모보다 뒤라서 `lo`가 되돌아가지 않는다 |
| 임의 순서 | 최악 O(V²) | 자식이 앞쪽에 있으면 `lo`가 되돌아가 같은 칸을 다시 훑는다 |

V = 커밋 수, E = 부모 연결 수.
`Repository`는 항상 생성 순서의 리스트를 넘기므로 실제로는 O(V + E)다.
결과의 **정확성**은 입력 순서와 무관하다. 순서에 따라 달라지는 것은 속도뿐이다.

### 최악 O(V²) 예시

`L1~L3`의 부모가 각각 `R1~R3`이고 순서가 `[L1, L2, L3, R1, R2, R3]`일 때:

```
R1 꺼냄 → L1(인덱스 0)이 후보가 됨 → lo = 0 으로 되돌아감
L1 꺼냄 → lo = 1 → L2, L3은 안 됨 → R2까지 훑음 (재탐색)
R2 꺼냄 → L2(인덱스 1) 후보 → lo = 1 …
```

되돌아갈 때마다 아직 못 꺼내는 칸을 다시 지나가서 m + (m-1) + … = O(m²).

## 5. 다른 방법과 비교

| | Kahn (이 프로젝트) | DFS 기반 |
|---|---|---|
| 방식 | 부모가 모두 나온 노드부터 꺼냄 | 깊이 들어갔다가 돌아오며 역순으로 쌓음 |
| 순환 검출 | 결과 개수 비교 | 방문 중인 노드를 다시 만나면 |
| 동률 규칙 | 후보 선택 규칙을 마음대로 정할 수 있음 | 방문 순서에 좌우됨 |

## 6. 이 프로젝트에서 쓰이는 곳

`LOG` 하나뿐이다. `PATH`와 `ANCESTORS`는 탐색 문제라서 BFS를 쓴다 (`merge-path-ancestors.md` 참고).

| 명령 | 문제 유형 | 알고리즘 |
|---|---|---|
| `LOG` | 전체를 줄 세우기 | 위상 정렬 (Kahn) |
| `PATH` | 두 점 사이의 최단 경로 | BFS (무방향) |
| `ANCESTORS` | 한 점에서 위로 모두 모으기 | BFS (부모 방향) |

BFS로는 "부모가 자식보다 먼저"를 보장할 수 없다. 병합 커밋은 부모가 둘이라, 둘 다 출력된 뒤에야 나와야 하는데 BFS의 층 순서로는 이 조건을 지킬 수 없기 때문이다.
